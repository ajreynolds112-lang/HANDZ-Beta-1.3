To integrate a Reinforcement Learning (RL) layer cleanly on top of **HANDZ-Beta-1.3** without breaking your existing boxing physics, stamina engine, or 200-string library, you need a **Hierarchical RL Architecture**.

Instead of replacing your existing framework, the RL model sits above it as a **Tactical Brain (Macro Layer)**, while your current code acts as the **Motor Engine (Micro Layer)**.

---

### **1. System Architecture: Macro vs. Micro Layer**

```
┌─────────────────────────────────────────────────────────┐
│              HIGH-LEVEL RL BRAIN (PPO)                  │
│ Evaluates distance, stamina, health, & player habits.   │
└──────────────────────────┬──────────────────────────────┘
                           │ Outputs: String ID (1-200) + Beat Scale
                           ▼
┌─────────────────────────────────────────────────────────┐
│            HANDZ EXISTING GAME FRAMEWORK                │
│ Executes inputs, calculates hitboxes, manages stamina,   │
│ handles slips (C), perfect blocks (V), & rhythm resets (B).│
└─────────────────────────────────────────────────────────┘

```

* **Micro Engine (Your Existing Code):** Handles input queues, frame data, hitboxes, stamina drain, stance switches (`Shift`), slips (`C` + arrows), feints (`F`), perfect blocks (`V`), and rhythm resets (`B`).
* **Macro RL Brain (New RL Agent):** Evaluates the ring situation every $N$ frames (or when a string finishes executing) and outputs **which string to run** and **at what speed (beat multiplier)**.

---

### **2. Wrapping HANDZ into a Gymnasium Environment (`handz_env.py`)**

To train an RL agent using libraries like **`Stable-Baselines3`**, you wrap your game state into a standard Gymnasium environment.

#### **A. Observation Space (State Vector $S_t$)**

Send a normalized array of floats (around 20-25 metrics) instead of raw pixels:

```python
observation = [
    # Positioning & Ring Geometry
    relative_distance_x,          # Distance between boxers (-1.0 to 1.0)
    ai_rope_distance,             # Is AI trapped in corner? (0.0 to 1.0)
    player_rope_distance,         # Is player trapped in corner? (0.0 to 1.0)

    # Health & Stamina Metrics
    ai_health_pct, player_health_pct,
    ai_stamina_pct, player_stamina_pct,

    # Combat States (Booleans as 0/1)
    player_is_attacking, player_is_blocking,
    player_is_ducking, player_is_feinting,
    
    # Stance & Modifiers
    ai_stance, player_stance,      # 0 = Orthodox, 1 = Southpaw
    ai_charge_armed,               # Is Charge (A) currently active?
    
    # Context & Round Scorecard
    current_round_number,
    estimated_judge_score_diff,   # Is AI currently winning or losing round?
]

```

#### **B. Action Space (Hierarchical Multi-Discrete)**

Rather than assigning actions to individual keys, the RL model selects high-level commands:

1. **`Action[0]` (String Index):** Selects String `1` to `200` from your combination library.
2. **`Action[1]` (Beat Delay Speed):** Continuous value between `0.0` and `1.0` (maps dynamically between `0.005s` and `0.5s` delay).
3. **`Action[2]` (Tactical Utility Trigger):**
* `0` = Standard Execution
* `1` = Trigger Rhythm Reset (`B`)
* `2` = Arm Charge Punch (`A`)
* `3` = Trigger Slip Counter Sequence (`C` + direction)
* `4` = Switch Stance (`Shift`)

### **3. Designing the Boxing Reward Function ($R_t$)**

To ensure the AI learns genuine boxing strategy (ring control, counter-punching, stamina conservation) rather than reckless spamming:

```python
reward = 0.0

# Offense & Counter Rewards
reward += damage_dealt * 1.0
if landed_during_player_recovery:
    reward += 2.0  # Big reward for counter-punching

# Defense Rewards
if triggered_perfect_block:
    reward += 1.5
if successfully_slipped_punch:
    reward += 1.5

# Boxing Discipline Penalties
if ai_stamina < 0.15:
    reward -= 2.0  # Heavily penalize gassing out / zero stamina
if whiffed_heavy_charge_punch:
    reward -= 1.0  # Penalize wasting power shots
if standing_passive_when_losing_scorecard:
    reward -= 0.1  # Force urgency when behind on points

```

### **4. Technical Implementation & Communication Pipeline**

Since `HANDZ` runs in Replit (using JavaScript/Node or Python/Pygame):

#### **Phase 1: Headless Fast-Training Pipeline**

1. Create a **headless training mode** in your code (runs the game logic without rendering canvas graphics or playing audio).
2. Run training at **100x real-time speed** using `Stable-Baselines3` (PPO algorithm) inside Replit or on local CPU/GPU.
3. Train for ~500,000 steps until the agent learns optimal string selection against player patterns.

#### **Phase 2: Exporting Lightweight ONNX Model**

1. Export the trained PPO policy network to an **ONNX format file** (`handz_ai_v1.onnx`, usually only **5 MB to 15 MB**).
2. Load `handz_ai_v1.onnx` into your main game engine using `onnxruntime` (available for both Node.js and Python).

### **5. Summary of Why This Framework Works**

1. **Storage Friendly:** Entire training setup + ONNX weights take under **1 GB** out of your **20 GB** Replit allocation.
2. **Zero Latency:** Inference takes less than **1 millisecond** per string decision.
